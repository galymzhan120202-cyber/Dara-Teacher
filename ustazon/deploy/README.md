# Ботты тұрақты іске қосу

Бір YouTube арнасына бір негізгі бот данасын қолданыңыз. Кезек пен жариялау тарихы сақталған ustazon/.state/ бумасын жоғалтпаңыз. Боттың қазіргі күндік жоспары — 2 қазақша, 1 орысша видео. YouTube арнасы әзірге байланыстырылмаған.

## Windows

- USTAZON_WORKER.cmd — ботты бақылаушы процесімен бірге іске қосады. Worker апатпен тоқтаса, бақылаушы қайта қосады.
- USTAZON_STOP.cmd — жұмысты сақтап, тоқтатуды сұрайды.
- USTAZON_STATUS.cmd — соңғы жұмыс күйін, кезекті, қателер мен келесі талпыныс уақытын көрсетеді.
- USTAZON_MAKE_3.cmd — бір күндік видеоларды жергілікті файл ретінде жасайды.

Windows жүйесіне кіргенде автоматты іске қосу үшін жоба түбіріндегі PowerShell терезесінен:

~~~powershell
.\ustazon\deploy\Install-UstazonStartup.ps1
~~~

Бұл сценарий тек ағымдағы пайдаланушыға арналған Task Scheduler тапсырмасын тіркейді. Құпиясөз сұрамайды, әкімші құқығымен орындауды талап ететін параметр қоспайды және PowerShell қауіпсіздік саясатын өзгертпейді. Орындауға ұйымның саясаты тыйым салса, USTAZON_WORKER.cmd арқылы қолмен іске қосуға болады.

Автоматты іске қосуды алып тастау:

~~~powershell
.\ustazon\deploy\Install-UstazonStartup.ps1 -Remove
~~~

Бұл тапсырма компьютер өшірулі немесе ұйқы режимінде тұрғанда ботты жұмыс істетпейді. Файлдар дайындалды; Task Scheduler-ге орнату осы жұмыс барысында орындалған жоқ.

[Task Scheduler ресми анықтамасы](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/register-scheduledtask).

## Linux сервері

Қазіргі Ustazon сайтын өзгертпейтін бөлек бума қолданыңыз, мысалы /opt/ustazon_bot. Node.js 24 немесе жаңарақ нұсқасы қажет. Native SQLite қолдауы пайдаланылады; осы компьютерде Node.js 26.1.0 арқылы тексерілді.

Жобаны көшірген соң сервердің өзінде тәуелділіктерді орнатыңыз:

~~~bash
cd /opt/ustazon_bot
node --version
npm --prefix ustazon ci --cache .npm-cache
npm run test:ustazon
node ustazon/daily.mjs health
~~~

Windows-та орнатылған node_modules бумасын серверге көшіріп пайдаланбаңыз. Қаріп пен музыка үшін fonts/ және music/ бумаларын сақтаңыз.

ustazon-bot.service.example ішіндегі User, WorkingDirectory, ExecStart мәндерін нақты серверге сәйкестендіріңіз. User — жобаны оқып, output және .state ішіне жаза алатын сервер пайдаланушысы; node жолын command -v node арқылы анықтауға болады. Сәйкестендірілген файлды серверде орнату:

~~~bash
sudo install -m 0644 ustazon/deploy/ustazon-bot.service.example /etc/systemd/system/ustazon-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now ustazon-bot.service
sudo systemctl status ustazon-bot.service
~~~

Серверде тоқтату және қайта қосу үшін:

~~~bash
sudo systemctl stop ustazon-bot.service
sudo systemctl start ustazon-bot.service
journalctl -u ustazon-bot.service -n 100 --no-pager
~~~

Сервис файлы — дайын үлгі. Нақты серверге орнату және сол серверде іске қосу орындалған жоқ. [systemd ресми анықтамасы](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html).

## Компьютерден серверге көшіру

1. Алдымен ескі жерде ботты тоқтатып, STATUS арқылы worker.running=false екенін тексеріңіз.
2. Жоба кодын, fonts/, music/, ustazon/.state/ және ustazon/output/ бумаларын көшіріңіз. .env.local, client_secrets.json және YouTube токенін тек өз серверіңізге қауіпсіз жолмен жеткізіңіз.
3. Жаңа серверде npm ci орындаңыз. .state/ бумасын жаңадан бос күйде жасамаңыз: онда жариялау түбіртектері мен аяқталмаған жүктеулер бар.
4. Бот бұрынғы Windows файл жолдарын жаңа жобаның жолдарына сәйкестендіреді. Видео ID-лері, контент белгілері және жүктеу session-дары сақталады.
5. Жаңа жерде health нәтижесін тексеріп, содан кейін worker іске қосыңыз. Ескі дананы қатар қоспаңыз.

SQLite дерекқорын ортақ желілік дискіге салып, екі серверге қатар жаздырмаңыз. Бір дерекқор аясында қатар процестерден қорғау бар; екі бөлек көшірілген дерекқор өзара байланыспайды.

## Резервтік көшірме және қалпына келу

Негізгі дерекқор — ustazon/.state/bot.sqlite. Қалыпты жұмыс кезінде оны жоймаңыз. Бұрынғы daily.json — көшірілген ескі тарих; жаңа жүйе оны жұмыс кезегі ретінде жаңартпайды.

Күн сайын .state/backups/ ішіне тексерілген SQLite көшірмесі жасалады; әдепкіде 14 күн сақталады. Дерекқор жоқ немесе бүлінген болса, бот ескі JSON-нан өздігінен жаңа кезек жасап жариялауды жалғастырмайды.

Көшірмеден қолмен қалпына келтіру алдында ботты тоқтатыңыз. Көшірме уақытынан кейін YouTube-ке шыққан видеоларды тексеру қажет: ескі көшірмеде сол кейінгі түбіртектер болмауы мүмкін. Мұндай жағдайда жариялауды өшірулі қалдырып, арна тарихымен сәйкестендіріңіз. Токен мен медиа файлдары SQLite көшірмесіне кірмейді; сервердің резервтік сақтау жүйесіне оларды бөлек қосуға болады.

## Қате кезінде

health.json және күндік .state/logs/ журналдары соңғы қатені көрсетеді. Журналға API кілті, OAuth токені және жүктеу session URL-і жазылмайды.

- Интернет немесе уақытша API қатесі: күту аралығы өсіп, жұмыс сақталған жерден жалғасады.
- Жергілікті тәуліктік лимит: келесі жергілікті күнге дейін жаңа Gemini сұрауы жіберілмейді.
- Қате кілт/токен: баптауды түзетіңіз. Worker баптауды әр айналымда қайта оқиды.
- Диск аз: жаңа генерация кідіреді; дайын MP4 пен жариялау тарихы жойылмайды.
- Жүктеудің аяқталғаны белгісіз: бұрынғы session тексеріледі. Ескірген немесе шешімі белгісіз session автоматты жаңа жүктеумен ауыстырылмайды.

Түзетілген тапсырманы қайта кезекке қою:

~~~bash
node ustazon/daily.mjs retry --job 2026-11-13-morning-kk
~~~

Бұл команда жарияланған видеоның ID-сін өшірмейді. Қолмен тексеруді талап ететін upload session-ды да тазаламайды. Әдеттегі уақытша қателерде retry командасы міндетті емес.

## Сақтау және контент

30 күн қолданылмаған дыбыс кэші, уақытша аудио файлдары және ескі журналдар тазаланады. Аяқталмаған жұмысқа керек дыбыс сақталады. Дайын MP4 файлдары, жеткізілген видеолар және жариялау түбіртектері автоматты жойылмайды. Бос орын 512 MB-тан азайса генерация тоқтатыла тұрады; шектер automation.json ішіндегі runtime бөлімінде.

Дәл бірдей мәтін, дауыс мәтіні, есеп және бір файлдың қайталама жүктелуі тексеріледі. Бұл барлық мағыналас видеоны адам деңгейінде таниды деген сөз емес. Ұзақ мерзімдегі мазмұн сапасы үшін жаңа расталған материалдарды knowledge.json-ға қосып отыру керек.

Тексерулер шынайы шағын MP4 құрастырады және API жауаптарын модельдейді. Бір жылдық кесте, үзілістер, жүктеу жауабының жоғалуы, апаттан қайта қосылу, бүлінген MP4, көшіру және резервтік сақтау тексерілген. Нақты YouTube жүктеуі арна байланыстырылғаннан кейін тексеріледі.
